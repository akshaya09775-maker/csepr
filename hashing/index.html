What's actually happening

01

Seed

The running hash starts at a fixed number, 7 — never zero, so an empty password still produces a real value.

02

Roll

Each character's numeric code is folded in: hash = hash × 31 + code. Every prior character still shapes the result.

03

Wrap

The result is wrapped with % 1,000,000,007, a large prime, keeping the number bounded and well spread out.

04

Encode

The final number is converted to hex, so it reads like a conventional hash string rather than a long decimal.

Educational demo only — not suitable for real password storage. Use bcrypt or Argon2 for that.
